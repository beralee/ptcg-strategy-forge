# 从牌组思路到可验证策略

本项目采用 PtcgDAP 已验证的策略思考方法，但把它约束在作者包当前真实支持的范围内：作者记录跨窗口意图，运行时仍只对当前公开窗口提出可重绑定的排序建议。

## 四层思考模型

### 1. Match Agenda

先回答整局目标，而不是先给卡牌排 priority：

- 最快与稳健的奖赏日程分别是什么；
- 当前需要保护哪一个引擎、攻击手或一奖桥；
- 对手会选择哪个可信目标来最快结束；
- 何时停止铺场并转入终结。

奖赏时钟以“攻击窗口”计数。当前能否攻击、为了保奖是否让自己的攻击窗口更慢，通常比自然回合数更重要。

### 2. 当前路线

把候选动作放进一条有边界的路线比较：

```text
公开前置条件
→ 当前合法动作
→ 精确资源支付
→ 对手可信回应
→ 当前奖赏结果
→ 下一攻击手连续性
```

Rule/Base 是永远可执行的 floor。adapter 只有在同层合法候选之间提供偏好；没有公共证明时，不得把“看起来更聪明”的动作写成越过 hard tier 或 veto 的规则。

### 3. 信息纪元

抽牌、检索、揭示、奖赏变化、随机结果和新交互窗口会改变公开信息。信息动作只打开一个检查点，不等于路线已经完成。

持久计划可以记住：

- 尚未解决的资源债务；
- 期望角色或稳定 UID；
- 必须保持的攻击窗口和连续性；
- 重观察后的条件后缀。

它不能记住旧 option index、旧分数、旧 legal frontier 或旧证明。每个信息检查点后必须重新观察和绑定。

### 4. 类型化交互

主动作偏好不自动解决后续交互。需要分别说明：

- 检索哪些角色或卡；
- 弃什么、保留什么；
- 能量分配到谁；
- 换位或出战目标；
- 伤害指示物和多目标分配；
- 何时允许合法 whiff 或空选择。

UCIS 已让引擎用统一标准窗口表达精确数量、分配、支付、换位、进化、攻击和伤害等交互；但 `.ptcgai` restricted IR 仍只支持有限的公开 predicate。引擎“能发布该标准窗口”不等于 data-only adapter“能表达任意跨窗口条件图”。无法表达的策略判断应写为明确限制和未来合同需求，不能伪装成已经运行。

## 资源、威胁和奖赏时钟

策略蓝图至少维护一份公开 Resource Ledger：支援者额度、手贴、备战位、检索/回收、攻击费用和下一攻击手债务。比较候选时同时问：

1. 当前是否完成最小致死或关键任务；
2. 对手的最佳可信回应是谁；
3. 退到备战区的多奖目标是否仍可被抓取；
4. 防守动作是否让自己慢了更多攻击窗口；
5. 资源投入是否超过当前路线的最小需要。

不确定性要保留为不确定性。已公开核销的抓取能力可以形成强 guard；“对手也许没有老大”只能作为风险偏好，不能写成确定性安全证明。

## 从蓝图编译到 adapter

`forge workspace create` 会生成 `STRATEGY-BLUEPRINT.md`。推荐顺序：

1. 写 Match Agenda、角色、资源债务和关键路线；
2. 标出信息动作及其重观察检查点；
3. 选择当前 IR 能表达的公开、当前窗口条件；
4. 把它们映射为 `acquire/deploy/fund/ready/execute/maintain/recover` 规则；
5. 让 Base Graph 保持所有合法性与最终裁决节点；
6. 为不能表达的部分记录限制，不增加自由代码、私有状态或未来索引。

## 场景不是动作快照，而是决策证明

每个 macro 的基础矩阵见[场景测试](03-SCENARIO-TESTING.md)。关键策略还应增加 metamorphic 配对：只改变一个事实，验证结论在准确阈值翻转，例如：

- 目标剩余 HP `250 → 251`；
- 可用能量 `3 → 2`；
- 剩余奖赏 `2 → 1`；
- 可信抓取 `available → publicly_exhausted`；
- 当前攻击窗口 `open → closed`；
- 目标 option 从 index 1 重排到 index 0。

失败必须归因到最早层：observation、identity、adapter predicate、Base adjudication、interaction 或 engine。不要先用 priority 掩盖身份和事实错误。

## 当前能力边界

Forge 当前作者包是 data-only、Windows-local，并为五套已审核 18.0 精确牌组提供可生成模板，支持公开当前窗口的受限规则开发。UCIS SDK 可解析标准窗口、精确选量、重绑定语义目标，并从公开 state 计算简单 prize clock/energy debt；这些 helper 不构成 Opponent Response Solver、任意牌组语义编译、模型调用或完整规则 engine parity。

蓝图和场景让这些思路可审查、可逐步迁移；真正的运行能力仍以包合同、Host 编译和可执行证据为准。
