# PTCG 学习型策略研发流水线

产出能在目标 Godot Host 中运行、能与冻结规则基线比较、能回滚的 `rules_with_model` `.ptcgai`。采用“成熟规则 → 可验证决策数据 → 小型 BC Actor → 实战纠错 → 有条件的群体 PPO”路线。训练方法不改变 Base/Host 的权威。

## 使用与范围

- 这是本路线的独立入口。不要加载或转交给 `ptcg-strategy-lifecycle`、`deck-strategy-iteration` 或其他旧策略研发 skill；直接读项目代码、合同和测试。旧包、公开论文与历史回执可以作为数据来源，不是旧 skill 的调用入口。
- 维护源在 Forge 的 `skills/ptcg-learned-strategy-pipeline/`；本机 Codex skills 目录保存可发现的安装副本。修改 skill 时同步两份并校验文件摘要，避免后续调用旧内容。
- 跟随用户明确的牌组、对手、预算和交付范围。没有指定时，首个试点选已有成熟规则和真实回执的玛俐长毛巨魔，固定精确 60 卡，先比较驾驶策略；`646600` 与 `800018501` 是不同牌表，不能混用教师、UID 或基线。
- 用户只要求创建 skill、设计方案或审查时，完成相应产物即可，不自动启动训练、对战或发布。要求研发时，持续完成已授权阶段，常规修复不逐步询问确认。
- 仓库修改权限按当前任务和各仓库 `AGENTS.md` 判断。创建本 skill 不授予修改外部 PtcgDAP、提交 Git、上传发布或生产安装的权限；已明确授予的权限无需重复请求。

## 开始与恢复

1. 确认实际 Forge 根目录，检查 `git status`，保留用户和其他任务的改动。修改行为前按该仓库 `AGENTS.md` 的阅读顺序阅读；不要从目录名字推定版本或强度。
2. 首次读 [当前能力与代码定位](references/capabilities.md)。这是 2026-09-18 的起点，启动新实验时用当前源码、`--help` 和精确回执重新核对；文档写了计划不等于接口已实现。
3. 新研究工作区从 [研发计划模板](assets/RESEARCH-PLAN.md) 建立 `research/PIPELINE-PLAN.md`。已有工作先读取它和最后回执，校验绑定的文件摘要，再从最早未通过的门继续。模板是研发记录，不是 Forge 命令输入或运行时 schema。
4. 固定基线包、牌表、引擎、SDK/张量/算子合同、对手和数据切分身份。工作树有未提交内容时记录实际文件摘要，不能只记 Git commit。修改这些依赖会使受影响的后续门失效。
5. 继续已有模型研发时读 [数据诊断与持续迭代](references/continuous-improvement.md)，先核对分情境覆盖、实际改选和已消费确认组，再确定本轮可检验假设。不要默认扩大网络、增加 epoch 或打开更多学习窗口。

## 阶段及通过条件

| 阶段 | 工作与通过条件 | 按需阅读 |
|---|---|---|
| P0 基线与可学习空间 | 找到可执行规则基线及回滚身份；按 context 统计 Base 裁决后的候选数、可学习窗口占比和规则唯一决定的原因；锁定实验范围 | [特征与集成](references/features-and-integration.md) |
| P1 公开特征合同 | 补齐决策所需的公开场面、自己手牌及候选语义；Python/Godot 投影、排序/重绑定、presence/mask 一致；信息不足时拒绝模型分支 | [特征与集成](references/features-and-integration.md) |
| P2 真实数据资格 | 决策前观察、当前合法选项、目标模型候选域、教师动作及 Host 接受形成闭合关系；先小批验证，再扩充；按整场及相关种子分组切分 | [数据与训练](references/data-and-training.md) |
| P3 BC 候选 | 训练小型前馈排序 Actor，按 context 验证；可用 GBDT 对照或蒸馏；导出满足当前 ORT 合同，规则 fallback 独立可执行 | [数据与训练](references/data-and-training.md) |
| P4 实战纠错 | 验证真实模型调用，收集模型自己走出的局面；按完整回合审核有害、有益、等价及未知改选，再补标重训；保留规则和前一模型作对照 | [数据诊断与持续迭代](references/continuous-improvement.md)、[数据与训练](references/data-and-training.md)、[验收与交付](references/evaluation-and-delivery.md) |
| P5 群体 PPO（条件阶段） | BC 的数据/导出/实战门通过，且用户任务包含 RL；先验收训练采样与轨迹接口，再用冻结历史策略和多牌组对手训练 | [数据与训练](references/data-and-training.md) |
| P6 配对验收与交付 | 冻结候选后使用未参与选择的新种子，与规则/BC/RL 基线逐层对照；场景、真实调用、干净整局、性能和回滚证据闭合 | [验收与交付](references/evaluation-and-delivery.md) |

阶段是依赖关系，不是每次重跑全部流程。已有门的输入摘要和证据仍有效即可复用。P3 是第一版模型包里程碑，不自动证明比规则更强；P5 不是交付 BC 包的前置条件。仅模仿自己的旧策略也不能宣称已经超越教师。

若 P0 的目标候选域尚无可审计来源，将相关覆盖统计标为未知并保持待验收；可以继续独立的基线审计和 P1/P2 接口建设，补齐后回填 P0。缺少候选域不等于零个合法候选，也不是停止所有研发的理由。用户任务已包含整局 RL 时，将模板 P5 从 `not_requested` 改为 `pending`，保留启动前置条件。

缺口在授权仓库内：先写聚焦失败用例，修复最早 owning layer，完成语义重排与相关负例，再重新验收。缺口位于未授权外部仓库：准备具体接口变更、失败证据及验收条件，继续独立可做工作，并只在确实需要时请求该具体范围；不得手工改 hash、伪装夹具或绕过 Host 来推进。

## 始终保持的决策合同

- 只有当前不可变 `select.option` 可选。Actor 输出同层分数和合法数量建议；Base 保留 legality、mandatory/terminal、hard tier、veto 和最终提交权。
- 每次接受动作后重新观察。跨窗口仅保存已授权的公开语义目标/稳定身份/债务；Actor 默认无状态，不能自行藏入 RNN memory、旧索引、旧分数或旧 proof。
- 自己可见手牌可入特征；对手隐藏手牌、牌序、盖奖身份、私有 RNG、另一座位的私有视角不入 Actor 或教师决策输入。终局结果可作训练标签，不可回流成当时的输入。
- 击倒、费用和路线可用性必须由当前公开事实与受审规则推导。未知能力或随机结果保留未知，不把可用交互清单当作完整规则正确性证明。
- 学习窗口由明确的 Host/合同 gate 分流。复杂多选未支持时走真实规则路径，不通过故意输出非法数量或触发异常“实现”分流。
- 包只带冻结数据模型与完整规则 fallback；不带 Python、原生插件或在线学习代码。导出之前检查真实 I/O、算子、尺寸和预算，不以“能转 ONNX”代替平台验收。

## 本机资源与证据

启动或恢复重型训练、对局、回放、评估前，必须读 [电脑稳定性保护](references/computer-stability.md)，核对当前运行器实际执行了保护，不能只依赖本段说明。Windows 64 GiB 主机重型任务串行，最多 4 workers；commit ≥70%、可用 RAM <12 GiB、输出/分页盘可用空间 <20 GiB 时不启动。运行中持续落盘采样，内存越界或输出/分页盘 <10 GiB 时停止本次拥有的进程树；监控或写盘失败同样不接受实验。保留系统/临时盘余量、进程内存、输出量和时长上限；不得覆盖 `PTCGABC_MAX_*` / `PTCGABC_MIN_AVAILABLE_GIB` 等保护变量。

先用不制造真实内存/磁盘压力的故障注入和短试运行验证，再恢复既定预算。压力触发、卡死或损坏输出必须保留失败目录，从最新完整 checkpoint/有效阶段恢复；不要补造结果、自动重试资源故障或无限运行。已有磁盘清理授权不等于今后可以自动删除用户数据。

每阶段记录实际执行、产物摘要、未通过项及下一步；缺少证明时标 `pending`/`failed`，不要填成功占位。最终报告区分：模型包可执行、公开窗口模拟、目标 Godot 实战、胜率结论、CABT 差分、设备与生产状态。

Kaggle 方法的来源、可复用内容与未开放范围见 [研究来源](references/research-sources.md)。无需每次重新联网；当需要新版本、最新公开代码或比赛状态时再核实原始来源。
