# P2–P5：真实数据、BC、纠错与群体 PPO

## 真实 trace 的最小闭合关系

每个训练样本关联：对局/相关种子组、决策者座位、教师包与引擎/合同身份、决策前公开视角、完整合法 options、当前窗口哈希、目标模型候选域及其 Base 依据、教师 accepted choice、单决策引擎提交见证。标签通过该次 tensorizer 的索引映射得到，不能用下一帧或观战视角补造。

原生录像完整性、网络来源认证、Host 接受、引擎提交见证、目标模型投影等价是不同条件。只缺一步的录像仍按其真实状态保留，不通过改 `evidence_kind`、`bc_eligible` 或删除字段晋级。自定义诊断字段只用于复核，不能顺势扩展 Actor 输入。

目标模型的 candidate frontier 由目标规则/Host 合同决定。教师与目标规则不同，需要在准确前置输入上验证目标 frontier；不能直接把教师 ranked indexes 当目标模型可选集合。标签不在目标域时保留明确排除原因，不扩权、不静默换标签。

单选教学排除 mandatory/terminal、单候选、无合格见证和目标域不明的窗口。dirty、拒绝、异常回退保留用于工程诊断；干净的正常规则分流与异常 fallback 要分开统计。数据集报告全部接受/排除计数，不能只报幸存样本。

## 数据规模与切分

起步预算可用约 20 局检查转换；合格后约 200–500 局形成初始语料。这是可调整的采样计划，不是质量阈值、最低计算承诺或足以证明强度的样本数。扩充依据是 context、牌组对局、关键资源状态和教师覆盖。

- 以成熟规则、受审人类纠正为教师，记录标签来源。Kaggle 录像若要导入，先解决具体 printing、合同和规则结果差异，不能按卡名或官方数字 ID 直接拼接。
- 胜局示范不保证每一步最优，败局也不意味着每一步错误。不要用整局胜负给每个候选制造正负动作标签。
- 同一对局的双方、双座位同种子、配对重跑、option 重排、人工变体和共同轨迹归入相关分组；先分组切分，再生成增广。避免同一根局面跨 train/validation/test。
- 词表/归一化/数据选择仅在训练集拟合；允许独立固定的受审卡表词表。使用验证集选 checkpoint；封存测试和最终新种子不参与纠错/选模，使用过后标记消耗。
- 记录 source/adapter/tensor/deck/teacher hashes、排除原因、重复冲突、分片摘要和 split seed。输入视角遵守公开边界；终局 outcome 是监督标签，不是决策输入。

## 小模型 BC

先做同层候选排序：输入共同局面与每个候选的语义，输出分数。初始考虑约 20 万–50 万参数的小型前馈网络，参数量按输入、性能和预算调整；这个范围不是保证支持的架构。

对有效候选使用 masked listwise/pairwise 目标，兼顾 context 覆盖，避免大量简单检索淹没关键窗口。明确规则 fallback 和 context gate；超出当前数量能力的样本单列。若需要 0..N、多目标或顺序选择，必须单独设计依赖选择的表示和数量/序列合同，不能把独立 top-k 当作已解决组合资源分配。

保留现有整数线性基线作接入对照。可选 GBDT 用于特征诊断、候选排序或教师；在验证/实战有价值时再蒸馏。检查当前算子 profile：CatBoost/LightGBM 原生导出、普通 Transformer 或 RNN 不自动符合 ORT allow-list。不要扩宽权限去迁就任意模型。

部署 Actor 始终只输出合同允许的分数与数量；训练阶段可以有 value/辅助预测头，导出时只保留可部署分支。目标 CPU、单批固定 shape、模型大小、所有候选负载及超时实测优先于参数估计。输出需整数时审查缩放、舍入、饱和、溢出和同分排序；不能依赖整数回绕产生偶然偏好。

导出验收包括训练实现与 ONNX/ORT 的原始分数（允许的精度合同）、整数输出、候选排序、最终 Host 动作/数量。用留出真实窗口和阈值相邻场景检验；不能只验证全零张量。量化后的行为差异必须单独统计，不用平均误差遮盖关键动作翻转。

## 模型轨迹纠错

BC 先验收能运行，再让模型走出自己的状态分布。记录模型调用、模型改选、规则分流、异常 fallback、最终接受动作及首个错误窗口。

对失败或资源浪费的局面：定位信息/identity/规则/模型的最早错误；由公开证据或教师给出合理选择。人工改标必须保留原选择、理由和反例来源；经过审核才入训练集。加入新训练轨迹后重新去重和分组，保留原验证集或显式升级切分，绝不把最后测试反馈回同一次确认实验。

每轮同时比较规则、上个 Actor、新 Actor。模仿准确率衡量教师一致性；策略强度由独立对局证明。若收益来自修复 fallback、卡效或 Base，单独归因，不能都算模型提升。

## 群体 PPO 的准入

只有任务包含整局 RL 且以下条件成立才启动重型 PPO：合格真实数据/公开投影、可部署 BC、目标引擎真实模型调用、独立规则基线、资源预算，以及**可验证的训练 rollout 接口**。

该接口至少记录每一步实际观察、合法且授权的 action mask、采样选择/多选序列、实际行为策略 log-prob、policy version、value、reward、done/truncation、座位与轨迹顺序。训练采样仍受相同 Host 合法性约束，不修改玩家包运行权限。

- Host 改写/拒绝动作或异常 fallback 时，不把提议动作的 log-prob 配给最终动作。按原因剔除整段或使用有依据的处理，并报告比例。
- mandatory/terminal 或训练 gate 外的强制规则步不能当成 Actor 自由选择；按明确定义的环境推进与奖励归属连接相邻可训练步。
- 多选如被学习，联合动作概率必须与实际采样顺序一致；首版单选时保持显式限制。
- 终局回报以胜/负/和为主。座位切换不改变回报归属；非法/dirty/引擎超时不能当普通输局训练。时间截断与真正终局分别处理。
- 使用冻结规则、历史 Actor 与不同牌组对手，登记采样权重。先通用对手下训练固定牌表，数据量和对局证据支持后再做专家路由。
- 先做短 rollout 与一次更新的正确性试验，再增加预算。每个 checkpoint 冻结并导出到真实部署路径评估，不能用训练专用动作权限比较玩家策略。

无状态部署不允许把训练中的隐藏记忆保留下来。可见历史若需要，作为受审输入升级；完整决策/GAE/采样能力未完成时，交付 BC 与缺口报告，不能把局部 bandit 命名成 full-game PPO。
