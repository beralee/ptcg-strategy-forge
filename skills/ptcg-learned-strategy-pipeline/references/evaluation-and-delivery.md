# P4/P6：真实引擎对照、晋级与交付

## 实验必须能回答具体问题

比较层次：冻结规则基线 → 相同规则加 BC → 相同规则加 BC 后 RL。牌表、Base/Host、fallback 或引擎同时变化时，补齐同条件对照，分别报告影响。需要换牌的实验应另开牌表分支，不能将驾驶改进和构筑收益合并。

实验前写下对手身份/权重、训练/验证/确认种子、座位安排、计算预算、主要指标、可接受退步与晋级规则。可用目标如“加权胜率提升约 5 个百分点”表达研发方向，但不能作为保证或在看完结果后临时更换指标。

## 逐层验证

1. **合同与行为**：聚焦 RED→GREEN、单事实阈值翻转、option 重排、目标消失/信息变化、多窗口重新绑定、mandatory/terminal/tier/veto、未知 UID/shape、隐私、正确数量和异常回退。
2. **构建与推理**：受影响工作区完整 check/双构建；CPU ORT 留出输入等价；记录 exact Actor/包 hash、warm latency、最大候选规模、加载行为和超时/内存。旧包路径保持兼容。
3. **模型引擎试运行**：先少量目标 Godot 整局，确认该精确包真的调用原生 ORT。分别统计 gated-to-rule、model_called、model_changed_choice、model_error/timeout、Host accepted/rejected；规则分流不算模型错误，模型故障回退不能隐藏在“零非法动作”中。
4. **固定开发对照**：相同冻结引擎、对手、种子与双方座位，记录胜负/和、错误、完整录像、关键战术与首次分歧。种子相同不保证策略分歧后的随机轨迹逐步相同，不声称完美消除方差。
5. **独立确认**：冻结最终包后使用未调参的新种子。例如五类对手 ×40 seed ×2 座位，每个版本 400 局；这是可按预算调整的设计，不是显著性的保证。与该候选配对的基线也必须在同条件下运行。

区分诊断人工链、引擎可达链和整局强度证据。不得从场景 GREEN 推导某条复杂路线已在引擎里实际完成。其他牌组历史通过也不能豁免当前模型的 native/Host 门。

## 整局完整性与统计

每局保存候选/对手/运行时摘要、seed、座位、终局及错误分类。引擎失败、身份投影失败、拒绝、缺失录像等必须保留在计划分母和失败表；整组不满足干净条件时不签发强度通过，不能删除失败对局后给出“干净胜率”。

既报告每个 matchup，也报告按预先权重汇总的收益、和局和不确定性。按相关 seed 分组处理双座位及同种子多对手的依赖，可用组级 bootstrap/置换；逐局独立假设不成立时不把简单区间当确证。

测试集用于一次事先约定的最终判断。结果不确定时如需扩充，在后续实验预先固定新增预算/停止规则，保留原结论；不重复抽种子直到显著。多次选模需要新确认集或事先定义的多重/序贯处理。

当模型几乎不调用、输入不能区分关键局面、模型改选全被覆盖或净收益来自规则变化时，报告真正原因，返回对应阶段。模型高模仿率、单次胜场增加或对自己很强都不足以认定泛化优势。

## 交付清单

- 精确 `.ptcgai`、Actor、规则 fallback、牌表/printing、版本与 SHA-256；明确开发签名身份和可用平台。
- `STRATEGY-BLUEPRINT.md`：Match Agenda、公开资源和奖赏路线、信息检查点、typed interaction、已实现/未实现能力。
- 研究计划/阶段回执，数据资格与切分摘要、训练代码/配置/checkpoint/导出身份；无需公开大体量原始日志或任何凭据。
- 场景和双构建、模型等价与性能、目标 Godot 调用、配对及独立对照证据。
- 回滚包 exact hash；若更换合同/运行时，也固定兼容回滚环境，不能只回滚 Actor。
- 结论明确是“模型可运行”“在指定对照中改善”“尚未证明更强”或“拒绝晋级”。未实现 RL 可以交付真实 BC 结果，不能冒称 RL 完成。

本地工作区验收、Godot 引擎见证、官方 CABT 规则一致、设备验收、线上资格和 production 分开列。交付研发包不隐含账号写入、上传、安装生产策略或外部仓库修改；按当前用户授权完成这些独立动作。
