# P0/P1：基线、公开特征与 Host 集成

## 冻结基线与衡量可学习空间

从现有可运行规则包开始，核对精确 60 卡、每个 printing、本地 UID、package identity/hash、规则/场景与真实引擎回执。目录名、版本号或旧报告中的高胜率不能替代当前文件摘要。恢复历史强基线优先于重新采用较弱 scaffold。

按实际 context 统计：窗口数、mandatory/terminal 数、规则唯一决定数、候选数分布、目标模型可选数、不可投影数、数量类型、规则/Host fallback。特别记录至少两个同层合法候选的窗口占比。

当录像没有目标模型 frontier，报告“目标域未知”及其数量，不能填成零候选或把教师排序当目标域。先完成可做的基线和原生资格诊断，推进 P1/P2 所需接口，获得可验证目标域后回填覆盖率；此前不签发可学习空间通过。

模型没有有效候选时，先解释 Base/route 的选择。若是事实/实现错误，按拥有该错误的层修复；若是合法策略约束，维持该约束。不要为了提高模型调用率删除 hard tier、veto 或确定终局保护。若需改变 Base 合同，单独记录理由、RED 用例和双端回归。

## 设计足够的信息，而非任意堆特征

为每个新增特征填写：语义、唯一数据源、何时可见、单位/范围、缺失表示、类别编码、计算 owner、Python/Godot 对照样例、依赖的规则资格。

优先特征族：

| 族 | 输入与用途 |
|---|---|
| 局势 | 双方剩余奖赏、牌库/手牌数量、先后手、支援者/手贴/撤退额度 |
| 己方资源 | 当前可见手牌、弃牌，进化桥、能量和检索/回收资源；不要把真实牌序或盖奖身份送入模型 |
| 双方场面 | 公开身份、HP/伤害、阶段、能量、道具、弱点/抵抗及可用特性；按 owner/zone/实体关联候选 |
| 动作语义 | 动作类型、效果来源、作用目标、资源支付、当前可证明的伤害/击倒/奖赏结果、候选与场面的关系 |
| 连续性 | 当前攻击窗口、后继攻击手所缺资源、换位/拉后排成本；未来路线可行性不确定时显式标未知 |
| 玛俐专项 | 进化与庞克泵感供能链、雪妖女压力、愿增猿可转伤和目标、暗影子弹集中拿奖、对手公开治疗/免伤响应 |

卡身份用审核词表/类别编码与语义属性，不能把 UID hash 的大小当卡牌价值。身份关联只使用已授权稳定公开标识，不能引入引擎对象或私有 locator。场上同名宝可梦仍是不同实例。

特征计算只反映决策时可知信息。对于伤害指示物放置与攻击伤害、特殊能量与基本能量、费用减免与能量单位分别编码。公开可推导的直接动作结果与估计的对手响应分别表达；不要把猜测的未来抽牌、老大或治疗当成确定事实。

## 先证明输入能区分要学习的决策

在训练前做成对场景：只改变目标 HP、能量、奖赏、进化前置或后继资源，要求投影确实变化。两个需要不同动作的局面被投影成相同输入时，先补投影，增加训练量无效。

同一语义 option 集合重排后，输入行与当前索引映射一致；不能把 `raw.index` 中的区域位置语义误当 option 列表序号删除。padding 不入候选，缺失不等于数值零。卡位变化应重新计算关联，跨窗口不复用旧映射。

## 版本化与最小集成

1. 明确变更 owner：公开观察/identity、tensorizer、Host 分流、Actor exporter 或数据适配。先有 focused RED。
2. 当前 generation 不足时建立新的受审 tensor profile，同时保留旧包路径；不在旧 hash 下更换特征语义。package v2 与 tensor profile v2 不能混为一谈。
3. 训练端、Forge reference 和 Godot 使用一致的 allow-list、词表、固定 shape、mask 和 candidate mapping。仅两端具备该 profile 才能签发模型可运行证据。
4. Forge SDK 从已授权受审来源机械刷新，执行仓库规定的 snapshot build/check，固定 source bytes。外部源未获修改授权时产出接口补丁设计并继续本仓库独立工作，不绕过来源锁。
5. 定义明确的模型启用 gate：context、单选/多选、信息完整性、合法候选数。第一版优先单选；不支持的多选/分配走规则。能力门属于执行合同，不能靠模型故意报错实现。
6. 验证 rules-only、模型禁用、模型启用、错误/超时四种路径；记录 Base authority 与旧包行为的兼容性。

## 跨窗口计划

蓝图保留 Match Agenda、奖赏路线、资源债务、信息检查点与 typed interaction。首版 Actor 从每个新局面重新计算选择；长期策略可以由终局训练信号逐步学到，但不能因此声称模型已执行完整条件计划图。

若需要公开历史/语义债务摘要，先证明 Host 已提供且训练端同构；否则作为独立版本化能力。禁止用私有 Python 缓存或 RNN 状态绕过无状态 Actor 合同。
