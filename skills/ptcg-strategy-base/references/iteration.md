# 复盘、实验与知识回流

## 先校验录像

两种受支持输入：

```powershell
.\.venv\Scripts\python.exe tools/strategy_base.py reflect-native --trace <原生录像目录> --seat 0 --report <新报告.json>
.\.venv\Scripts\python.exe tools/strategy_base.py reflect-bench --bench-report <report.json> --candidate-sha256 <精确包SHA256> --report <新报告.json>
```

原生路径验证 manifest、逐记录链、公开观察/选项指纹、Host 接受与单决策提交见证；明确指定本人座位。Bench 路径先验收干净整局审计、包摘要、完整轨迹链和每个窗口，只提取候选座位；一条命令最多 32 局、每轨迹 128 MiB，可以重复 `--game-index` 限定局。拒绝截断、dirty、非法输出、Host 异常回退、摘要漂移或未知 frame。

Bench 的整局提交数不能冒充每个窗口的一对一提交见证；报告会明确该差异。完整性也不自动证明服务端来源认证。旧摘要、图片和只有结果的录像无法补造决策前公开输入。需要可播放本地复盘时，可在该任务实际需要且相关 skill 可用时调用 `build-ptcg-local-replay-review`；其重建证据不能替代原始输入。

自动探针覆盖：有合法攻击却空过；零前场伤害且存在备战目标；后排就绪而前排卡住；空过潜在终结攻击；牌库极低时使用可选卡效。它们只是线索，零伤害招式可能没有后排效果，可选能力可能不抽牌，空过也可能合理。

## 从假设到改动

1. 优先合法性/身份/输入故障，再处理攻击断档和终结错失。记录首个有因果意义的分歧，不能从最终输赢倒填当时未知信息。
2. 对候选动作审查完整支付、交互后缀、反制、后继与奖赏变化。定位最早责任层；查精确印刷，必要时重新核实原始规则来源。
3. 原始选择只证明“发生过”；另写经过审查的期望选择。`workspace.debugging.from_replay` 默认保留原选择，不能直接当作修复教师。Base authority 必须取自对应公开审计，缺失时标为显式模拟输入。
4. 用现有 `workspace.debugging.explain/compare/counterfactual/generate` 和场景工具建立 RED。加入同语义重排、错误所属方/实体、缺费用/目标消失、信息结果有/无分支、mandatory/terminal、hard tier/veto、未知 UID、隐藏字段。关键阈值做单事实翻转。
5. 改最小 owner。新路线编译通过后做完整链；链前缀失败不能继续累计后缀通过。后续手写 frame 只证明窗口序列决策，不证明可达性。
6. 跑受影响工作区 `check`。通过后再用监督器串行短试，核对调用、非法输出、回退、拒绝、丢记录和轨迹。问题未清零不能用胜率豁免。

## 强度与回滚

冻结基线/候选的包、牌表、SDK、引擎、对手、种子和座位。开发种子用于调试；一经看过确认组，它就被消费，后续版本需新确认组。基线与候选必须同运行时同位置配对，按相关种子分组分析，记录负转胜和胜转负及第一处分歧。跨运行时的 11/20 与 72/100 不能组成提升率。

预算服从用户任务和机器保护。默认先完成一个可解释假设的小规模开发试验，不无限扩轮、追单场或隐式安排后台任务。候选未过强度门时保留为开发候选，规则基线仍可回滚；合同通过、行为修复、真实执行改善和整体胜率提升分别报告。

## 经验回流

- 单卡 UID、特殊费用或一个 matchup 阈值：更新该牌组 profile/蓝图和永久反例。
- 多牌组重复的资源计算、阶段编译、身份或录像审查缺口：增加通用测试和第二种牌组结构，修改框架。
- 工作流程造成错误结论或重复遗漏：小范围修订本 skill 的对应参考，不把所有反例累积成禁令。
- 修改 skill 后用 `skill-creator` 的验证器核对结构，复演一次实际构筑或复盘任务，同步维护源/本机副本并记录摘要。

晋级至少回答：究竟改了什么；哪个公开事实改变决策；哪些负例仍关闭；原版与新版的精确身份；真实替代分支是否执行；是否有未见种子的支持；回滚到哪一个包。没有证据的项保留 pending。
